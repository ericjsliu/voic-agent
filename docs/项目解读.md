# 智能座舱语音对话代理 — 项目解读

> 解读日期：2026-09-11  
> 仓库：`voic-agent`  
> 依据：当前代码实现（不仅是 README）

本文是对仓库的架构与实现解读，用于后续改功能时快速对齐边界。设计目标与真实代码不一致的地方单独写在「实现落差」一节。

---

## 1. 项目是什么

这是一套**云端侧**智能座舱语音对话代理（Smart Cockpit Voice Dialogue Agent），把驾驶员的 ASR 文本（当前用 HTTP 文本模拟）转成结构化任务图（TaskGraph），再由编排器校验、按风险等级执行，最后通过 MQTT 与车辆侧交互。

它不是「LLM 直接开车」的助手，而是 **架构路线 C**：

- LLM / 规则规划器只负责生成 **schema 约束** 的 TaskGraph 草稿
- **编排器（Orchestrator）** 才是执行与安全闸门
- 车辆只应接收编排器验证后的 TaskGraph，而不是原始 LLM 输出

当前仓库同时包含：

| 角色 | 位置 | 说明 |
|------|------|------|
| 云端 Agent | `app/main.py` | FastAPI，规划 + 编排 + HTTP/WS |
| Mock 车辆 | `app/vehicle_mock/` | MQTT 订阅下行、模拟 ack/导航事件 |
| Mock RAG | `app/mock_rag/` | 车型手册混合检索，端口 8001 |
| Web 测试台 | `web/` | React + Vite，nginx 托管 `web/dist`，端口 3000 |
| 基础设施 | `docker-compose.yml` | Mosquitto、Redis、上述服务 |

v1 明确不做：视频/clip 知识检索、真实 CAN/车机接入、生产级鉴权。

## 2. 架构路线 C 在本仓库里长什么样

一次请求的逻辑链路：

```
ASR文本 (HTTP /dialogue)
  → SessionManager 取/建会话
  → ContextAssembler 组装上下文
  → Planner 生成 TaskGraph（LLM，失败则规则）
  → 立即 HTTP 返回 TaskGraph，并 WS 广播
  → 后台 Orchestrator 校验 + 按依赖执行
  → 领域适配器 validate/execute
  → 执行结束后 MQTT 下行 cockpit/agent/taskgraph
  → Mock 车辆写回 cockpit/agent/writeback
```

关键不变量（README 声明，代码部分遵守）：

1. **下行安全**：车辆不应看到未校验的 LLM 草稿。
2. **L0 / L1 / L2**：查询立即执行；控制立即执行但可撤销；高风险必须确认，15 秒超时取消。
3. **L1 拒绝不重试**：车辆因档位/车速拒绝时，不会再走 Planner。
4. **Knowledge 仅文本**：只支持 `query_manual`，强制 citations；无命中则不编造。
5. **Chitchat 隔离**：无 schema 约束、不写长期记忆。
6. **POI 必须预解析**：导航目标下行前要有坐标，不能把「家」原样发给车机。
7. **换驾清空**：切换 `driver_id` 时清影子状态与记忆切片。

                                 ├─ redis:6379

## 4. 一次对话的真实代码路径

入口：`POST /dialogue`（`app/main.py`）。

1. **会话**  
   有 `session_id` 则 `SessionManager.get_session`，没有则创建。活跃会话主要活在进程内字典 `active_sessions`。

2. **上下文**  
   `ContextAssembler.assemble` 拼：
   - 最近 5 条 utterance
   - 影子状态（telemetry 合并进 `shadow_state`）
   - 记忆切片（`user_prefs` / `frequent_destinations` / `music_prefs`，按 `driver_id`）
   - 当前位置（telemetry 的 lat/lon）

3. **规划**  
   `Planner.plan`：有 LLM 客户端则 JSON mode 生成 TaskGraph，再 `_resolve_pois_in_taskgraph`；失败或无 Key 走 `_plan_with_rules`（关键词：导航/车窗/锁车/空调/音乐/手册，否则闲聊）。

4. **同步返回**  
   HTTP 立刻返回 TaskGraph；同时 WS 向该 session 广播 `{type: taskgraph}`。  
   Web UI 据此画 JSON，并检测 L2 弹出确认。

5. **后台执行**  
   `BackgroundTasks` 跑 `execute_and_publish`：
   - `Orchestrator.execute_taskgraph`（先 `adapter.validate` 全图，再按 `depends_on` 并行执行就绪步骤）
   - L2 进入 `WAITING_CONFIRM`，最多 15 秒
   - knowledge / chitchat 在云端直接完成
   - vehicle / nav / media / calendar 的 adapter.execute 目前只组 payload，状态标 `pending`，编排器却**立刻标 COMPLETED**（简化）
   - 整图执行结束后才 `publish_taskgraph` 到 MQTT

6. **L2 确认通道**  
   WebSocket 消息 `{type: l2_confirm, task_id, step_id, accepted}` → 组装 `WritebackEnvelope(CONFIRM_RESULT)` → `orchestrator.handle_writeback`。

## 5. 核心模块

### 5.1 SessionManager（`app/session/session_manager.py`）

- `create_session` / `get_session` / `update_session_activity`
- `switch_driver`：改 `driver_id`，删除 `shadow_state:{sid}` 与 `memory_slice:{sid}`
- `end_session`：清会话及相关键
- 会话 TTL 意图为 24h，但见第 8 节白名单问题

### 5.2 ContextAssembler（`app/session/context_assembler.py`）

Planner 的唯一上下文来源。telemetry 每次覆盖影子字段。记忆切片只读白名单长期键，**assemble 路径不会写入偏好**。

### 5.3 Planner（`app/planner/planner.py`）

- OpenAI 兼容客户端（DashScope）
- 系统提示固定 domain/action 与 L0/L1/L2 规则
- 后处理：导航 `goal.poi_name` 用 `NavigationAdapter.resolve_poi`
- `_validate_safety`：`nav_to` 坐标不得为 0
- 规则 fallback 可在一句里同时命中多条规则（例如「打开车窗，同时播放音乐」→ 两步，无 `depends_on`，编排器并行）

### 5.4 Orchestrator（`app/orchestrator/orchestrator.py`）

自定义状态机，不是通用 workflow 引擎。

步骤状态：`pending → ready → executing → completed | failed | cancelled | waiting_confirm | confirm_timeout`。

- 依赖：`depends_on` 全部在 `completed_steps` 才就绪
- 同批就绪步骤 `asyncio.gather` 并行
- L2：设 15s deadline，循环 sleep 0.5s 等 writeback 或超时
- `handle_writeback`：确认接受则当场 `adapter.execute`；拒绝/超时标失败；还处理 `vehicle_ack` / 导航事件 / media / calendar ack
- `pending_downlink` 保存「已验证」TaskGraph，供 `get_downlink_taskgraph`

### 5.5 领域适配器（`app/adapters/`）

统一接口：`validate(step, shadow_state)` / `execute(step, context)`。

| 域 | 文件 | validate 要点 | execute |
|----|------|---------------|---------|
| vehicle | `vehicle.py` | 锁门/后备箱需档位 P；天窗需车速 0；空调温度 16–30 | 返回 pending payload |
| navigation | `navigation.py` | `nav_to` 必须有 goal 且坐标非 0 | 带 goal + route_prefs |
| media | `media.py` | 音量 0–100；播放必须有 query | pending |
| calendar | `calendar.py` | `add_event` 要 title + start_time | pending |
| knowledge | `knowledge.py` | query 非空 | 调 Hybrid RAG，拼 top3 文本 + citations |
| chitchat | `chitchat.py` | 始终通过 | 原样返回 `response` |

车辆约束动作集合：

- 需 P 档：`door_lock` / `door_unlock` / `trunk_open`
- 需静止：`sunroof_open` / `sunroof_close`

### 5.6 TaskGraph schema（`app/schemas/taskgraph.py`）

三层：`TaskGraph` → `Task`（branch）→ `Step`（domain + 强类型 action）。

动作级别：

- **L0**：查询类，立即执行（导航规划、日历、知识、闲聊）
- **L1**：控制类，立即执行（车窗、空调、媒体）
- **L2**：高风险，确认后执行（`door_lock`、`trunk_open`）

schema 比规则规划器覆盖更全，例如 `seat_heat_*`、`nav_cancel`、`play_radio` 等，规则 fallback 并未全部实现。

### 5.7 Writeback（`app/schemas/writeback.py`）

车辆/云端上行信封：`task_id + step_id + branch_id + event + status + reason + ts`。

事件：`vehicle_ack`、`confirm_result`、`nav_route_started`、`nav_arrived`、`nav_rerouted`、`media_ack`、`calendar_ack`、`knowledge_done`。

状态：`success` / `failed` / `rejected` / `accepted` / `declined` / `timeout`。

### 5.8 Memory Store（`app/memory/store.py`）

Redis，连不上则进程内字典。设计是**两阶段写入**：`set` 进 pending，`dialogue` 后台结束时 `commit()`。

长期记忆白名单前缀：

- `user_prefs:`
- `vehicle_config:`
- `frequent_destinations:`
- `music_prefs:`

不在白名单的 key，`set` 直接 skip。会话、utterance、影子状态因此**不能**经 store 持久化（见第 8 节）。

### 5.9 Hybrid RAG（`app/rag_client/client.py` + `app/mock_rag/`）

Agent 用 httpx POST `{RAG}/v1/hybrid-search`，filters 为 `model` / `version`。失败返回空列表，KnowledgeAdapter 视为无命中。

Mock 数据含 ModelA / ModelB 2024 手册片段（空调、车窗、中控锁、天窗、座椅加热等），按关键词打分 + 车型过滤。

### 5.10 Mock Vehicle（`app/vehicle_mock/mock_vehicle.py`）

订阅 `cockpit/agent/taskgraph`：

- L2：1 秒后自动 `confirm_result=accepted`（与 Web UI 确认是另一条路径）
- vehicle / media / calendar：约 0.5s ack
- navigation：2s `nav_route_started`，5s `nav_arrived`

并周期性发 telemetry（档位 P、车速 0、北京坐标等）。

### 5.11 Web UI（`web/src/`）

- `App.tsx`：会话、WS、发 `/dialogue`、收 taskgraph/writeback
- `ChatPanel`：对话与 L2 确认按钮
- `InfoPanel`：TaskGraph JSON、writeback 流、遥测
- `ConnectionSettings`：Agent URL、Driver ID、车型/版本

遥测 state 目前声明了但未见从 WS/MQTT 持续更新（`useState` 初值为 null）。

## 6. MQTT 主题

| 方向 | 主题 | 载荷 |
|------|------|------|
| 下行 | `cockpit/agent/taskgraph` | 校验后的 TaskGraph JSON |
| 上行 | `cockpit/agent/writeback` | WritebackEnvelope |
| 上行 | `cockpit/agent/telemetry` | 车辆遥测 |

Agent 订阅 writeback / telemetry；车辆订阅 taskgraph。

当前 telemetry 回调只打印日志，没有写回 `orchestrator.shadow_state`（影子主要靠 HTTP 请求里的 telemetry）。

## 8. 实现落差（读代码后的结论）

这些点与 README「已实现」表述不完全一致，后续改功能时不要被文档误导。

### 8.1 MQTT 下行发生在编排结束之后

`execute_and_publish` 先 `await execute_taskgraph`，再 `publish_taskgraph`。  
因此车辆收到 TaskGraph 时，云端编排器往往已经把步骤标成完成。Mock 车辆的 ack / 自动 L2 确认，对**当次**等待中的编排帮助有限。

L2 的有效确认路径是 **Web UI WebSocket**，不是 Mock 车辆 MQTT。

### 8.2 编排器对车控类步骤「假设立即成功」

`_execute_step` 在 L0/L1 调用 adapter 后直接 `COMPLETED`，没有等 `vehicle_ack`。`handle_writeback` 里的 ack 分支基本是预留。

### 8.3 记忆白名单把会话态写废了

`session:` / `utterances:` / `shadow_state:` / `memory_slice:` 都不在白名单。  
`set_json` 会 skip。后果：

- 会话跨进程无法从 Redis 恢复（同进程靠 `active_sessions`）
- 最近对话、影子状态无法经 store 跨请求保存；影子只能靠每次请求带 telemetry

长期偏好键设计了，但对话路径几乎不 `set` 这些键，白名单两阶段写入目前接近空转。

### 8.4 MQTT 回调线程与 asyncio

`on_mqtt_message` 在 paho 后台线程里 `asyncio.create_task(...)`。该线程通常没有跑着的 event loop，writeback 从 MQTT 进编排器这条路径不可靠。WS 路径不受影响。

### 8.5 Knowledge 过滤未自动带上车型

`KnowledgeAction` 有 `model_filter` / `version_filter`，但 Planner（含规则）没有从 telemetry 的 `model`/`version` 填进去。Web UI 虽有车型设置，不传给 knowledge step 则 Mock RAG 不过滤。

### 8.6 规则规划的导航抽取很脆

`_extract_destination` 取关键词后第一个空白分词；「导航到机场」在无空格中文里可能整段当目的地，依赖 `resolve_poi` 的模糊包含（「机场」在「导航到机场」中）才能命中。

### 8.7 Web 遥测面板

前端 `telemetry` 未接入 MQTT/接口更新，右侧车辆状态容易一直空。

## 10. 扩展时该动哪里

加新领域（README 步骤仍然适用）：

1. `app/schemas/taskgraph.py` 增加 Action 类型，并加入 `Step.action` Union
2. `app/adapters/` 新适配器，实现 validate/execute
3. `orchestrator.py` 注册到 `self.adapters`
4. `planner.py` 系统提示 + 规则 fallback
5. 测试

接真实车辆：替换 `vehicle_mock`，让 adapter.execute 走真实控制，并把 MQTT 下行提前到「校验通过、执行前」，同时让编排器真正等待 ack。

接真实 RAG：改 `HYBRID_RAG_BASE_URL`，保持 `/v1/hybrid-search` 契约（`query` / `filters` / `top_k` → `hits[].text|score|citation`）。

## 12. 一句话总结

本项目是座舱语音的 **TaskGraph 中枢**：用 schema 把 LLM 关在规划侧，用编排器做 L0/L1/L2 与域校验，用 MQTT 模拟车云。骨架完整，适合做规划/编排/新域扩展；车辆闭环、记忆持久化、遥测写回仍偏演示级，以第 8 节为准。
